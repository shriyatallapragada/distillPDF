# DistillPDF — capture extension

Stage 1 of the pipeline. This Manifest V3 extension reads the answers you pick
from a NotebookLM chat page and hands them to a local helper that writes
`study-notes.pdf` and `study-notes.html` to your Downloads folder. There is no
`chat.json` download and no network call. It runs in desktop Chrome on Windows,
macOS and Linux; mobile browsers cannot install MV3 extensions, so phones use
`mobile/capture.html` from the project root instead.

## Install

From the project root, run `./install.sh` (or `install.bat` on Windows) once.
Besides installing Python dependencies, that registers the native messaging
host Chrome uses to reach the local renderer. Then:

1. Open `chrome://extensions`.
2. Enable **Developer mode**.
3. Click **Load unpacked** and choose this `extension/` folder (or the unzipped
   `dist/DistillPDF-extension.zip`).
4. Reload the extension once after the installer so it sees the host.
5. Open a NotebookLM chat. The picker appears on the right.

The popup finds the NotebookLM tab even if you open it from another tab or
window. If auto-detection misses it, the popup shows a **Choose the chat tab**
list — click your chat there. A **Reload chosen tab and retry** button handles
pages that were still loading.

To build the zip yourself, run `python3 scripts/package_extension.py` from the
project root.

## Use

- Answers found on the page are listed with a checkbox. **All start unchecked**;
  tick only what you want, or use **Select all** / **Clear**.
- The cleaner removes recognized standalone greetings and sign-offs at the ends
  of the selection. Replies that contain study material are kept.
- To export only a passage, select the text on the page and click **Add
  highlighted text**.
- Click **Build PDF + HTML**. The local helper runs the whole pipeline and
  writes both files to Downloads (or to the project's `out/` folder if macOS
  blocks Downloads). The popup shows the build status until the files appear.
- **Refresh answers** re-scans after you ask a new question.
- The toolbar icon opens the same picker as a popup. **Settings** holds the
  page selectors, in case NotebookLM changes its layout.

If the helper is not registered, the picker reports "Local helper" instead of
downloading anything — re-run the project installer once.

## Code map

| File | Role |
| --- | --- |
| `manifest.json` | MV3 entry point; content script, popup, options, background worker, fixed ID. |
| `background.js` | Forwards selected answers to the native host and returns the saved file paths. |
| `selectors.json` | All NotebookLM DOM hooks in one editable file. |
| `selectors.js` | Loads those defaults and merges saved overrides from Options. |
| `converter.js` | HTML → Markdown, including exact KaTeX `<annotation>` recovery. |
| `content.js` | Scrolls virtualized chats, splits turns, tracks selections, adds highlights, requests the build. |
| `popup.html`, `popup.css`, `popup.js` | Toolbar popup backed by the same content-script state. |
| `options.html`, `options.js` | Edit selectors and optional enhancer notes. |
| `palette.css`, `content.css` | Styles scoped to the injected picker. |
| `icons/` | Toolbar icons, generated by `scripts/make_icons.py` inside this folder. |
| `test/fixture.html`, `test/run_test.py` | Chrome CDP test of capture, selection, whitespace and the build bridge. |

The host side lives in the project root: `scripts/native_host.py` runs the four
stages and `scripts/install_native_host.py` copies it into
`~/Library/Application Support/DistillPDF/` (macOS), `%LOCALAPPDATA%\DistillPDF\`
(Windows) or `~/.local/share/distillpdf/` (Linux) before registering it. Chrome
cannot read helper files inside `~/Documents`, so the installed copy lives
outside the project folder.

## Verify

From the project root:

```bash
.venv/bin/python extension/test/run_test.py
```

It loads the unpacked extension in Chrome, checks that user prompts are
discarded, LaTeX comes from the annotations, whitespace is preserved, and only
selected answers are sent to the build bridge.
